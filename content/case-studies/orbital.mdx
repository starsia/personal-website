## Problem

We wanted to a create a game that students can play to explore degree choices. Like many others, it was our first year in university.

## My Role

Software Engineer, responsible for building the game in Unity with C#, setting up authentication for players to save their progress. Set up the story engine for path choices. Set up bundlers to deploy package to online game markets.
Story writer, designing the DAGs (Direct Acyclic Graphs) using Ink, so I could programmatically ensure the story could unfold the way I wanted.

## Approach

- **Sprints:** Make weekly checkpoints to review progress and achieve those goals.
- **Testing:** I did A/B testing where I played it through myself, and also got friends to play to test and find bugs.
- **Deployment:** Ensured the game was bundleable and easily playable on the web.
- **User satisfaction:** Player's progress should be saved, hence the need for authentication features for returning players.

## Outcome

A game that works and can be played online! Check it out here: [Parallel uNivUSes](https://starsia.itch.io/parallel-univus)

## What I'd improve next

It would have been great if I could set up a CI/CD pipeline to immediately bundle the recent push to main onto the game platform.
